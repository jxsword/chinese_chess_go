# 11 开发执行手册（Go 版）

> 沿用 Electron 版 11 手册的执行模型与模板，命令与验收流 Go 化；
> **新增 §4"里程碑验收流"（用户手动验收门）与 §7"文档-代码同步纪律"**（用户要求：测试过→提交→手测→修复→验证→再提交；进度记录；不出现代码领先文档）。

## 1. 执行模型

1. AGENTS.md 常驻（每次会话自动读取）；
2. **一里程碑一全新会话**（会话粘贴 §3 对应里程碑模板）；
3. 子任务串行循环（§2 五段模板），一任务一 commit；
4. 里程碑收尾：复审（§5）→ 质量门 → PROGRESS.md 更新 → **用户手动验收** → 合入 main（可选打 tag）；
5. 会话纪律：不连做两个里程碑；引用文档编号而非粘贴全文；代理想改架构即停，走 DR 流程。

## 2. 子任务五段模板

```text
【范围】只做 <T 编号+标题>，涉及 design_docs/<编号 §节>，参照实现 <electron 文件锚点>
【先写测试】按 09 文档对应节：金标准对拍/快照/表驱动用例先行（红→绿）
【验收】质量门四项全绿 + 本任务专属验收（11 §任务表）
【禁止】超出范围的重构；意译协议；跳过/删除用例变绿；引入白名单外依赖
【提交】feat(mN): 描述（Decision: DR-xxx 尾行；PROGRESS.md 同步勾选）
```

## 4. 里程碑验收流（用户手动验收门，**每里程碑必经**）

```text
1. 代理完成该里程碑全部子任务（自动化测试先行、逐任务 commit）→ 质量门全绿
2. 代理更新 docs/PROGRESS.md（完成项勾选、已知问题、手测指引）
3. 【暂停】代理明确列出"请手测清单"，等待用户验收
4. 用户手测：
   - 无 bug → 回复确认 → 代理提交里程碑收尾（tag 可选）→ 进入下一里程碑
   - 有 bug → 用户列出现象 → 代理按 §5.2 修复（禁止删/跳用例变绿）→ 回归全绿 → 再提交 → 回到第 3 步
5. 纪律：验收通过前不开工下一里程碑；修复 commit 不得混入新功能
```

## 5. 复审与修复提示词

### 5.1 里程碑代码复审（验证门前两轮，沿 Electron 版）
- 第一轮·语义一致性：对照 design_docs/{对应文档} 逐节检查 1:1——协议文本逐字（05 §2）、算法参数（03 §2 难度表/05 §5 旋钮公式/DR-006 参数表）、行为锚点（Electron 01 文档 文件:行号）。
- 第二轮·缺陷扫描：竞态（迟到响应/输入锁/动画窗口）、取消链（requestId/context 全覆盖）、兜底三态收口、goroutine 异常传播、错误消息泄 Key、`-race` 报告。
- 输出 P0~P3 缺陷清单（文件:行号 + 设计依据）；P0/P1 立即修复回归，P2/P3 记 docs/KNOWN_ISSUES.md。

### 5.2 测试失败修复（沿 Electron 版）
先判实现错还是金标准错；改金标准必须给原版源码依据并单独 commit；禁止删/跳用例变绿；输出失败原因分类统计。

### 5.3 回归护栏（合入 main 前，沿 Electron 版）
对照 AGENTS.md 10 条铁律逐条自检（grep 验证 #1 纯 Go 包 import 面/#3/#4/#8/#10 可机器检查项），输出自检表；任一不满足即中止。

## 6. 常见跑偏与纠偏指令

| 跑偏信号 | 纠偏指令 |
|---|---|
| 代理"优化"提示词措辞/改正则 | 恢复 Electron 版 05 §2 原文，快照测试是权威，禁止意译 |
| 代理在前端直接 fetch LLM 端点 | 违铁律 #4，改走 internal/llm/transport + 绑定 |
| 代理把领域逻辑写进 React 组件 | 违铁律 #1/#分层，移入 internal/* |
| 代理引入全局单例 store | 违铁律 #6，用 createGameStore 工厂每局一实例 |
| 代理重写优化搜索/评估/排序 | 违铁律 #9，逐行翻译 electron TS 版，对拍兜底 |
| 代理给 LLM 请求加思维链开关或漏发关闭参数 | 违铁律 #10/DR-005，恒发按预设映射，无开关 |
| 代理把重复治理推迟到后续里程碑 | 违 DR-006，按 10 文档 M1/M2/M3 落位执行 |
| 代理擅自加依赖 | 撤回；说明理由并等确认（DR 流程） |
| 代码领先文档多个提交 | 违 §7，先补文档再继续 |
| 长会话质量下降 | 立即收尾 commit，开新会话粘贴 §3 模板继续 |

## 7. 文档-代码同步纪律（用户要求）

1. **先文档后代码**：任何行为/接口/参数变更先改 design_docs/ 对应章节（同一 commit 或文档先行 commit），再动代码；
2. 每个子任务 commit 同步勾选 docs/PROGRESS.md 对应条目；
3. 每里程碑收尾 PROGRESS.md 必含：完成清单、验收门结果、性能实测数据、已知问题（KNOWN_ISSUES 链接）、下一里程碑手测指引；
4. 禁止代码领先文档多个提交；发现漂移立即停下补文档。
