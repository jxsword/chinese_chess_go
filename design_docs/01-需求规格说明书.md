## 7. 差异一：重复局面裁决前置（对 E-F01 对弈流程的增量）

沿 electron-DR-018 的行为规格（详细状态机见本文档集 02 §7）：
k=2 单方长将 → 非阻塞警告；k=3 单方长将 → 判负；k=3 双方全程将军 → 不变作和；
k=3 无人全程将军 → 判和（对手为 AI/LLM 自动接受，玩家弹确认框）；k≥4（玩家曾拒绝）→ 强制判和。
Go 版在 M1（裁决纯函数）/M2（VM 四收口点与 UI 接线）/M3（引擎 L1/L2）即全部到位。

## 8. 差异二：LLM 通信强制关闭思维链（对 E-F20 配置的增量）

- Electron 版：`disableThinking` 为可选配置（默认识图/助手开、对弈关），仅发 `enable_thinking:false`。
- **Go 版：请求构造层恒发关闭参数（按预设映射），UI/配置不提供开关；存储 schema 无该字段**。
  映射规则与 JSON 形态见本文档集 05 §3.1（DR-005）。
