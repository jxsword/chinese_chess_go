## 1. 总体架构（不变）

本地裁决 + 远程提议：本地规则内核生成合法清单（唯一事实源），LLM 只能从清单中选；五层过滤 + 重试反馈 + 兜底链（builtinAi/resign）。

## 2. 提示词协议（逐字沿用 Electron 版 05 §2）

- **Prompt v1**：systemV1（坐标约定 列 a-i/行 0-9；只从「合法着法清单」选；回复唯一格式 整行`着法: 起点-终点`；禁止解释/推理/markdown/多行）+ userV1（`【当前局面 FEN】`+`【轮走方】`+`【最近着法】≤12 手`+`【合法着法清单（共 N 条…）】`坐标逗号+空格 join+`【输出】仅一行…`）+ retryFeedback。
- **Prompt v2**：systemV2(side, withBucketGuide)（`分析:` 段 ≤100 字 + 最后一行`着法: 起点-终点`；candidate 模式附分档引导）+ userV2（FEN+`【棋盘图】`ASCII+轮走方+`【对局着法】≤60 着+重复检测警示（isInverse 相邻回退判据）+注解清单行 `b2-e2(炮二平五,吃卒,将军)` 或 candidate 分档 ` — 最佳/均势`）+ retryFeedbackV2 + vetoFeedback。
- **注解分桶** `scoreBucket(cpDiff)`：≤30 最佳/均势｜≤100 略亏｜≤250 明显亏（约半子）｜≤600 大亏（丢一马/一炮级）｜否则 致命。
- Go 版实现于 `internal/llm/prompt.go`/`parser.go`/`annotation.go`；**快照测试锁定全文**（golden 从 Electron 版测试快照复制基准）。

## 3. HTTP 请求与传输层

### 3.1 请求构造（`internal/llm/config.go`）——DR-005 思维链强制关闭

公共字段（沿 Electron 版）：`model`（trim）、`messages[2]`（system/user）、`temperature: 0.3`、`stream: true`、`max_tokens`（v1=4096 / v2=8192）；URL 归一化 `requestUrl(baseUrl)`（trim→去尾斜杠→非 `/chat/completions` 结尾则补）；鉴权 `Authorization: Bearer {key}`（空 Key 不带头）。

**思维链关闭参数（DR-005，Go 版与 Electron 版的唯一请求差异）——恒发、无开关，按端点预设映射**：

| 端点预设 | 关闭参数 JSON（请求顶层） | 依据 |
|---|---|---|
| DashScope / Qwen 系（含识图预设 qwen-vl-max） | `"enable_thinking": false` | DashScope Qwen3 顶层布尔开关 |
| 智谱 GLM（glm-4.5 及以上） | `"thinking": {"type": "disabled"}` | 智谱 thinking 对象参数 |
| DeepSeek / Kimi / OpenAI / OpenRouter / 自定义 | `"enable_thinking": false` | 无思维链或未知参数被忽略，无害 |

- 规则：**构造函数无条件注入**（按 `LlmPreset.ThinkingStyle` 字段选择形态；自定义预设走兜底形态）；任何调用路径（对弈/识图/测试连接/求解辅助/MatchRunner）不可绕过；不存在"开启思维链"的代码路径。
- 预设表（沿 Electron 版 LLM_PRESETS）：智谱 `https://open.bigmodel.cn/api/paas/v4`（glm-4-flash，ThinkingStyle=glm）；DeepSeek `https://api.deepseek.com/v1`（deepseek-chat）；Kimi `https://api.moonshot.cn/v1`（moonshot-v1-8k）；OpenRouter `https://openrouter.ai/api/v1`；OpenAI `https://api.openai.com/v1`；自定义。识图预设：DashScope（qwen-vl-max，ThinkingStyle=dashscope）、智谱 glm-4.5v、OpenAI、OpenRouter。

### 3.2 传输层（`internal/llm/transport.go`，替代 Electron 版 main 进程 LlmProxy）

- `net/http` 流式 POST；`bufio.Scanner` 按行读（半行跨 TCP 分包由 scanner 缓冲重组；`Buffer` 上限调大防超长行截断）。
- **超时模型（沿 05 §3.2）**：空闲超时 = 两次数据块最大间隔（每块重置计时器），默认 60s、clamp 5~600s；**总上限 = 空闲×4** 独立计时器；二者触发 `cancel()` + error 事件，错误文案逐字沿用（`空闲超时（{N}s 内无响应数据，可在对局设置中调大）`/`总耗时超过 {N}s（…）`）。
- 取消：`Cancel(requestId)` → context cancel，幂等，之后无任何事件（迟到丢弃在前端适配层收口）。
- HTTP ≠ 200：截响应体前 160 字符 + `annotateModelHint`（命中 `streaming translation`/`invalid_parameter_error`/`input.messages` 附模型类型误用提示）。
- **SseAssembler（逐字翻译 sse.ts）**：空行/`:` 心跳行丢弃；非 `data:` 行忽略；`[DONE]` → ended；JSON 解析失败忽略；顶层 `error` → LlmApiError（计一次重试）；`choices[0].delta.content` 正文缓冲、`delta.reasoning_content ?? delta.reasoning` 思维链缓冲（**兼容双字段名**）；`pickAnswer()`：正文非空取正文，否则退思维链全文。

## 4. 五层过滤管线（逐字翻译 parser.ts）

1. SSE 重组（上）→ 2. `normalizeReply`（剥 ``` 围栏、删零宽 `[\u200b-\u200f\uFEFF\u2060]`、toLowerCase、全角 U+FF01–FF5E 逐码位 −0xFEE0）→ 3. 提取（`MOVE_PATTERN = /([a-i])\s*(\d)\s*[-–—~到至]?\s*([a-i])\s*(\d)/g`；多坐标对时**优先取最后一个「着法:」标记后**的第一个匹配，否则取最后一个坐标对；`LABELED_PATTERN = /着法\s*:/g`）→ 4. `decodeCell`（col 0-8/row 0-9 越界 null）→ 5. **白名单精确字符串匹配**（Map key；铁律 #3）。失败原因文案逐字沿用（`无法从回复中解析出着法`/`着法 {code} 不在合法清单中`/`第 {N} 次调用失败：…`）。

## 5. 单手棋总决策流程（参谋制，逐值翻译 hybridPlayer.ts）

- 三模式 `advisorMode = off | candidate | gate`；off 委托纯 Prompt v2 LlmPlayer。
- 流程：全量合法清单（空 → noLegalMove）→ `FindBestMoveEx(fen, {depth: advisorDifficulty+1, topK: K, timeLimitMs: 5000})` → 池 = candidate ? topK 短名单 : 全量 → 循环 ≤maxAttempts 调用/提取/匹配 → 兜底链。
- **旋钮公式（逐值）**：K = `min(8, max(3, 3 + floor(blend/20)))`；否决阈值 = `80 + trunc(320 × clamp(blend,0,100)/100)`（blend=100 不否决）；否决复评深度 = depth−1。
- **否决-再问-代走**：pick 相对最佳损失 > 阈值 → vetoFeedback 文本重问一次；二次仍超阈/失败/无效 → 采用引擎最佳代走，note=`已由参谋否决（两次选择均造成{分桶}的损失），改为引擎最佳着法`，fromFallback:true（**不走模型失败降级分支**）。
- 兜底链：模型失效 → builtinAi 代走（note=`…已由内置 AI 兜底走子`/candidate 模式=`…已由参谋（内置引擎）代走`，fromFallback:true）或 resign 判负（按设置）。
- `LlmConfig` 四字段中**不再有 disableThinking**（DR-005；关闭参数在 config 层恒发）。凭据三槽位 `llm_config_red/black/assistant` 沿用。

## 6. LLM 求解辅助（solveAssist）

沿 Electron 版：SOLVE_ASSIST 系统提示词 + `proposeSolveFirstMove` → `IsWinningFirstMove` 裁判（04 §3）；通过/不通过的文案与重试口径逐字沿用。max_tokens 用 v1 档 4096。

**配置来源（Go 版扩展，DR-009）**：读 `llm_config_assistant` 槽；助手槽三字段全空时运行时借用对战配置（优先级 黑→红），authSlot 随来源槽（DR-010 闭环），仅存在于本次请求内存、**不写入助手槽**；借用时 toast 提示来源。助手槽部分填写 = 独立无效配置，不借用（沿 DR-012 边界）。

## 7. 视觉识图（vision）

沿 Electron 版 vision.ts：VISION_SYSTEM_PROMPT/网格输出协议/`validateVisionKings`/`visionGridToFen`；请求**非流式**多模态，temperature 0.1、max_tokens 4096、**恒发关闭参数（dashscope 预设 → enable_thinking:false；glm-4.5v → thinking:disabled）**；识图人工校正流（08 §4）不变。

**配置来源（Go 版扩展，DR-009）**：同 §6——助手槽全空时借用对战配置（黑→红），authSlot 随来源槽、不落盘；借用时消息区注记"已临时借用 X 方对战配置（不写入研究助手配置）——对战配置可能不支持识图"（对话模型识图必败，错误文案经 annotateModelHint 提示改用视觉模型）。
