# 04 残局求解器设计（Go 版）

> 继承：`/home/ssy/proj/chinese_chess_electron/design_docs/04-残局求解器设计.md`（§1~§8 领域算法与 TS 实现 `src/packages/solver`
> 逐行翻译；其 6 个验证 FEN 金标准与状态机口径不变）。本文记录 Go 版差异：context 取消与数据结构 Go 化。

## 1. 核心语义（不变）

- 证明式求解：`Solve(fen, timeLimit)` 返回 `solved（含解）/ noSolution（证明无解）/ timeout`；
- 已将死/已困毙、非法局面（缺王）语义与 Electron 版一致；
- 迭代加深 AND/OR：攻方 OR 节点（存在一着制胜即真）、守方 AND 节点（所有应着均被制胜才真）。

## 2. Go 版结构（T6.1 实现定稿）

```go
// internal/solver/endgameSolver.go —— 形状沿 Electron 版 TS SolveResult
//（前端组件层零逻辑改动的消费契约，08 §1；04 §1"核心语义不变"）：
type Options struct {
    TimeLimitMs int              // 0=未设 → 缺省 30s；<0 → 1 小时兜底
    MaxPlies    int              // 深度上限（半着数）；0=未设 → 缺省 9
    Ctx         context.Context  // 取消（工作室关闭页/重新求解）
}
type Solution struct{ Moves []rules.Move }
type Result struct {
    Status        Status       // "solved" | "noSolution" | "timeout"
    Solutions     []Solution   // 首解着法序列（多解枚举）
    Elapsed       int64        // 用时（毫秒）
    SearchedPlies int          // 实际搜索到的深度（半着数）
}
func Solve(fen string, opts Options) (Result, error)   // 非法 FEN → rules.FenFormatError
func SolveIsUnique(result Result) bool
func IsWinningFirstMove(fen string, firstMove rules.Move, opts Options) (bool, error)
```

- 置换表：沿 Electron 版表项语义（winAt/failAt 按局面+轮走方记"已在 r 半着内
  证明"）；Go 版键用 `uint64` Zobrist（本包私有键表、固定种子 xorshift64，
  **独立于引擎搜索键**，避免互相污染；语义等价 TS 的完整 FEN 串键——FEN 亦含
  轮走方）。超时/取消以哨兵错误沿递归传播（等价 TS SearchTimeout 异常控制流）。
- 多解枚举（_enumerate/_extendLine/_findWinningReply）与着法排序（将军 > 吃子
  子力 > 其他；同分稳定排序保 TS 枚举顺序）逐行翻译。
- 协议层 `internal/solver/protocol.go`：Runner/Handle 同 engine 包 DR-003 口径
  （goroutine + ctx 取消注册表、入口/出口双复查取消），wire 载荷对齐前端
  `src/api/solverProtocol.ts`（`{status, solutions, elapsed, searchedPlies}`）。

## 3. isWinningFirstMove 验证接口（LLM 求解辅助裁判，05 §6）

`IsWinningFirstMove(fen, move, depth)` 沿 Electron 版语义（单着验证：走该着后守方全部应着均被制胜）——LLM 求解辅助用其判定模型首着是否"真的赢"。

## 4. 求解状态机与入库

`none → solving → solved/noSolution/timeout`，入库（07 §1.1 solve_status）与工作室三 Tab 联动（08 §4）口径不变；context 取消 → 状态回 `none`（不残留半程结果）。

## 5. 并发与性能

- 求解跑独立 goroutine（铁律 #7），取消经 ctx 传递到递归深处（每 512 节点探针
  检查 deadline/取消）；协议层把取消收口为 canceled 错误（取消后的 timeout
  结果不作有效应答）。
- 验证门：6 个内置验证 FEN（多解/无解/超时/已将死/非法/缺王）结果与 Electron 版
  一致——金标准以常量内置于 `internal/solver/golden_test.go`（逐项移植 Electron
  版 `test/solver/solver.spec.ts`，其源为 Flutter 版 endgame_solver_test.dart /
  docs/phase4/03 内置数据）。
