# 04 残局求解器设计（Go 版）

> 继承：`/home/ssy/proj/chinese_chess_electron/design_docs/04-残局求解器设计.md`（§1~§8 领域算法与 TS 实现 `src/packages/solver`
> 逐行翻译；其 6 个验证 FEN 金标准与状态机口径不变）。本文记录 Go 版差异：context 取消与数据结构 Go 化。

## 1. 核心语义（不变）

- 证明式求解：`Solve(fen, timeLimit)` 返回 `solved（含解）/ noSolution（证明无解）/ timeout`；
- 已将死/已困毙、非法局面（缺王）语义与 Electron 版一致；
- 迭代加深 AND/OR：攻方 OR 节点（存在一着制胜即真）、守方 AND 节点（所有应着均被制胜才真）。

## 2. Go 版结构

```go
// internal/solver/solver.go
type Options struct {
    TimeLimitMs int
    MaxDepth    int
    Ctx         context.Context // 取消（工作室关闭页/重新求解）
}
type Result struct {
    Status      string   // "solved" | "noSolution" | "timeout"
    Solution    []rules.Move // 首解着法序列
    FirstMove   *rules.Move
    Verified    bool     // isWinningFirstMove 校验通过
}
func Solve(fen string, opts Options) (Result, error)
```

- 置换表：沿 Electron 版置换表键（FEN/哈希）与表项语义；Go 版键用 `uint64` Zobrist（复用 internal/rules 或 engine 的哈希表实现——**求解器键独立于引擎搜索键**，避免互相污染）。
- 多解枚举（_enumerate/_extendLine）与着法排序逐行翻译。

## 3. isWinningFirstMove 验证接口（LLM 求解辅助裁判，05 §6）

`IsWinningFirstMove(fen, move, depth)` 沿 Electron 版语义（单着验证：走该着后守方全部应着均被制胜）——LLM 求解辅助用其判定模型首着是否"真的赢"。

## 4. 求解状态机与入库

`none → solving → solved/noSolution/timeout`，入库（07 §1.1 solve_status）与工作室三 Tab 联动（08 §4）口径不变；context 取消 → 状态回 `none`（不残留半程结果）。

## 5. 并发与性能

- 求解跑独立 goroutine（铁律 #7），取消经 ctx 传递到递归深处（每节点/每深度迭代检查）。
- 验证门：6 个内置验证 FEN（多解/无解/超时/已将死/非法/缺王）结果与 Electron 版一致（其 `docs/phase4` 口径 + 测试资产复制到 `internal/solver/testdata/`）。
