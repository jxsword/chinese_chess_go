## 1. 算法总览

Negamax + Alpha-Beta + 迭代加深 + 静态搜索（Quiescence）+ MVV-LVA 着法排序——算法结构与 Electron 版 search.ts 一致，逐行翻译。

## 3. 数据结构（Go 化，沿 electron-DR-007/008）

- 棋盘：`[90]int8` 一维（15 种带符号编码 −7..7，0 空）；`EngineBoard` 含 `redTurn` 与 Zobrist 键（§4）。
- 走法：整数 packed（from/to/captured 位域，位分配逐字翻译）；排序键内嵌 packed 高位（MVV-LVA）。
- 零分配：走法缓冲按 ply 预分配（`moveBufs` 风格 → Go `[][]int` 池），搜索热路径零堆分配。

## 4. L0 Zobrist 哈希（DR-006 前置；electron final §2 的 Go 版规格）

- **键**：Go 直接用 `uint64` 单键（比 TS 双 32 位干净）；表 `tables [15][90]uint64`（pieceCode −7..7 → 下标 code+7）+ `turnKey uint64`（首版起草残留的 TS 双表形状 `[2][15][90]` 已按"单键"口径勘误）。
- **PRNG**：固定种子 xorshift64（种子 `0x9e3779b9`，黄金比例常数；Marsaglia 移位 13/7/17；**键值序列跨进程确定**——Go 版键值不要求与 TS 一致，但测试以确定性快照锁定）。惰性 `sync.Once` 初始化。
- **增量维护**：`FromFen` 全量重建；`ApplyMove(from,to)`/`UndoMove(from,to,captured)` 严格互逆、对称异或（xor 自逆，无需撤销栈）；code=0 异或退化为空操作；暴露只读 `ZobristKey() uint64`。
- 测试（09 §2.2）：①初始局面键确定性快照；②FromFen 全量键 === 逐 Apply/Undo 重建键；③固定种子随机对局 120 步"增量键 === 全量重建键"；④同局面异轮走方键不同；⑤吃子改变键。

## 5. 主搜索流程

沿 Electron 版 search.ts：`Search{ maxDepth, deadlineMs, randomness, shouldAbort(ctx), historyCounts }`；
- 迭代加深 + 根节点；deadline 每 64 节点检查（超时抛 `SearchAbort`——Go 用 error sentinel，`run()`/`runScored()` 内捕获返回部分结果，语义一致）；
- qsearch 只展开吃子；将军延伸等待遇逐行翻译；
- 无将杀/困毙返回 null（Dart 口径）。

## 6. 重复治理 L1/L2（DR-006 前置；electron final §3/§4 的 Go 版规格）

### 6.1 L1 搜索内重复检测（search.go）

- **入参**：`SearchConfig.HistoryCounts map[uint64]int`（nil = 整段关闭，零开销，旧行为=与 Dart 口径逐位一致）。
- **路径栈**：`pathKeys [MaxPly]uint64`（MaxPly=24，按 ply 覆盖写）；根局面在 `iterate` 开局压入 pathKeys[0]。
- **检测**（negamax 入口）：①路径栈线性回扫 ≤23 次 uint64 比较，第 1/2 次同键罚 `PATH_REPEAT_PENALTY=[50,150]` 厘兵、**第 3 次及以上返回 0（和棋分）**；②全局历史：ply≤3 且 count≥2 时 `evaluate() + GLOBAL_REPEAT_PENALTY×(count−1)`（=100）；**count=1 不罚**（防误伤正常巡回）。命中即 return（剪枝，不展开子树）。
- **范围**：qsearch/searchEvasions 不压栈不检测（吃子线不可能成环）。
- 被标记着法分数 = 落子后静态评估 − 惩罚×(count−1)，**精确无搜索噪声**（命中即剪枝）——测试断言逐位。

### 6.2 L2 根节点历史回避（chessai.go FindBestMove）

```go
type FindBestMoveOptions struct {
    Difficulty  int      // 1-5，clamp；0=未设（Go 零值）即缺省 3
    HistoryFens []string // 缺省/空 = 关闭（行为与 Dart 口径逐位一致）
    Ctx         context.Context // 取消（与 deadline 同节奏探针）
}
func FindBestMove(fen string, opts FindBestMoveOptions) *Move
```

- **历史表构建**（引擎侧单源，electron-DR-019）：`buildHistoryCounts(fens)` 一次性把每个 FEN `FromFen` 后取 `ZobristKey()` 计数；**无效 FEN 静默跳过**；空表返回 nil → 整体关闭。**页面/调用方只传 FEN，不做哈希**。
- **两阶段**：常规搜索得 best 后，`postCount(best)==0` 直接返回（绝大多数快速路径）；命中历史才在剩余时限（`max(remaining,100)`ms）补一次全窗口 `runScored`。
- **`pickAvoidanceMove`（导出纯函数供直测）**：
  1. 阈值内（`AVOID_THRESHOLD_BASE[difficulty] × 系数`）且落子后非重复的候选 → Fisher-Yates 随机取一（随机源可注入）；
  2. 无候选且 best 为将军（长将形态）→ 强制选非将军非重复的最高分着法，底线 `≥ bestScore − FORCED_CHANGE_FLOOR(500)`；
  3. 底线内无候选或 best 非将军 → **保留原着交 L3 裁决**（劣势方靠重复求和是规则内合法策略）。
- **参数**（逐值搬移）：`AVOID_THRESHOLD_BASE={1:200, 2:200, 3:100, 4:50, 5:30}`；系数 bestScore>200→×0.5（优势求变）、<−200→×2.0（劣势可重复）、否则 ×1。

### 6.3 参谋接口不接受历史参数（可复现铁律）

`FindBestMoveEx(fen, {depth=6, topK=5, timeLimitMs=5000})`（根节点强制全窗口、真实分差、Top-K 降序）与 `EvaluateMove(fen, move, {depth=4})`（1-6 层、2s 上限；走完即杀返回 MATE_SCORE；非法/自将返回 null）**签名不含 HistoryFens**——与 Dart/TS 口径逐位一致，对拍不受 DR-006 影响。

## 7. goroutine 模型（替代 Electron 版 §6 Worker）

- 调用形态：`App.EngineFindBestMove(req)` 起独立 goroutine 跑 `FindBestMove`，`ctx` 取消（每 64 节点与 deadline 同节奏轮询 `ctx.Err()`）；结果经 Wails 事件回传或方法返回（短计算）。
- **取消语义**（沿 electron-DR-009）：取消=调用方丢弃语义收口——Go 搜索收到取消即中止返回，**迟到结果由前端按 requestId 丢弃**；协议层收口：ctx 已取消时 `Handle` 直接回 `{ok:false, error:"canceled"}`（文案对齐前端 `CANCELED_ERROR`），不把取消后的部分结果当有效应答；同步兜底（goroutine 不可用不存在于 Go，但保留 `FindBestMove` 同步直调路径供测试与 CLI）。
- **wire 缺省约定**：Wails 绑定参数无 optional——前端对未设参数传 `0`（`p.difficulty ?? 0` 等），Go 绑定层按"0=未设→取该接口缺省值"解释（difficulty→3；depth/topK/timeLimitMs→6/5/5000；evaluateMove depth→4）；显式传 1~N 恒按原值。
- 消息形状：内部协议保留 `{id,type,payload}` / `{id,ok,result|error|progress}`（`internal/engine/protocol.go`），便于 fake 注入测试（09 §2.4）。
- 性能门：难度 5 应答 ≤7.5s（5s×1.5 容差）保留；Go 实测数据记入 PROGRESS（预期显著优于门）。

## 8. MoveSource 抽象（沿 Electron 版 §7）

```go
type MoveSourceResult struct {
    Status       string // "ok" | "noLegalMove" | "failed"
    Move         *rules.Move
    Note         string
    FromFallback bool
}
type MoveSource interface {
    DisplayName() string
    NextMove(ctx context.Context, b *rules.Board, history []rules.Move) (MoveSourceResult, error)
}
```
`ChessAiPlayer(difficulty)` 为引擎实现；`LlmPlayer`/`HybridLlmPlayer`（05 §5）为 LLM 实现。返回 move 必为合法着法，页面 playMove 仍终审（铁律 #3）。
L2 历史入参引擎侧单源（electron-DR-019 口径）：`ChessAiPlayer.NextMove` 从 board+history 自行推导 fenHistory——深拷贝当前盘逐手 `UndoMove` 回放，收集每个中间局面的 FEN（含当前与起始），顺序与 VM `fenHistory`（起始→当前）一致；接口签名保持 `history []rules.Move` 不变，调用方无需感知哈希（§6.2"页面只传 FEN"的同源延伸）。

## 10. 金标准对拍口径（09 §2.2）

- `testdata/golden/engine.json`（Dart 提取，与 TS 版共用）：固定 FEN 上 findBestMoveEx 逐层 best/bestCp/topK **逐位一致**（同分排序不参与对拍）；
