# 08 UI 与交互设计（Go 版）

> 继承：`/home/ssy/proj/chinese_chess_electron/design_docs/08-UI与交互设计.md`（页面/动画/防错清单，Go 版前端为其**移植**）。
> 本文记录移植边界与差异：§1 移植清单、§2 api 适配层、§3 重复裁决交互（DR-006 前置接线）。

## 1. 移植清单（frontend/ = Electron 版 src/renderer 的移植）

| Electron 版 | Go 版 frontend/ | 移植方式 |
|---|---|---|
| src/renderer/app（路由/主页/全局设置） | 同路径 | **原样复制**（改 import 路径） |
| features/board（BoardView/boardArt/boardLayout/sidePanel/四对局页/useRepetitionJudge） | 同路径 | 原样复制 |
| features/{puzzle,record,solver,studio,settings} | 同路径 | 原样复制 |
| stores/（createGameStore 工厂/gameVm） | 同路径 | 原样复制 |
| workers/（engineClient/engineProtocol…） | **删除**——引擎调用改走 `App.Engine*` 绑定（goroutine 在 Go 侧） | 见 §2 |
| ipc/（client.ts，window.api 消费方） | src/api/（重写为 Wails 适配层，**接口形状不变**） | 见 §2 |

- 页面路由 7 入口（残局选关/人机对战/人机 LLM/LLM vs LLM/双人对弈/残局工作室/棋谱库）与主题色板不变。
- **不移植**：electron-vite 特定代码（preload 相关）；其余组件层零逻辑改动。

## 2. api 适配层（唯一改动面）

- `frontend/src/api/wailsAdapter.ts`：实现 Electron 版 `window.api` 的**相同 TS 接口**（llm.chat/cancel/testConnection、db.*、store.*、secure.*、corpus.*、dialog.*、clipboard、engine.*、events）：
  - invoke → `window.go.main.App.Xxx(...)`；事件 → `window.runtime.EventsOn/Emit`（requestId 过滤逻辑从原 ipc client 平移）；
  - **绑定命名空间（M2 手测勘误，F2）**：Wails v2 以绑定结构体所在 **Go 包名**挂载方法表（本项目 `package main` → `window.go.main.App`，wailsjs 生成物同口径）。曾误用 `window.go.app.App` → 桌面窗口内探测恒失败、静默回落 mock（存档/设置/凭据/剪贴板全部内存化）。client.ts 探测、本适配器与 engine/solver/parser 三客户端统一以 `main.App` 为准；
  - **生命周期补偿（M2 实现期补充）**：Wails v2 后端无窗口 blur/minimize 事件（07 §2 映射表 Electron 侧 win.on('blur')/('minimize') 无 Go 等价物），适配层在 `createWailsApi` 时附加 WebView `window.blur` 监听，失焦即向 onLifecycle 订阅者派发 `blur` 相位（最小化在主流平台伴随失焦）；`close`/`before-quit` 相位仍由 Go 侧 OnBeforeClose 发出。除此之外组件层零逻辑改动。
  - `frontend/src/api/mockAdapter.ts`：Electron 版 dev:web 的 mock IPC 层移植（无窗口开发 + Playwright E2E；不触网）；
  - 启动时按 `import.meta.env` 选择适配器（wails 检测 `window.go` 存在与否，与 Electron 版 window.api 探测同构）。
- 组件只 import api 接口类型，不感知后端（保持铁律：领域逻辑不进组件）。

## 3. 交互规格（沿 Electron 版 §2~§6，要点重列）

- 棋盘：SVG 绘制；布局 `cell=min(w/9.6,h/10.6)`、交点 `origin+col/row×cell`；命中换算 rect 缩放；点击选中→合法目标高亮→动画→落子。
- 走子动画 220ms（easeOutCubic 贝塞尔）两阶段启动；**权威结束信号 = 220ms 定时器**（transitionend 不可靠）；动画期间忽略新点击；动画结束才真正落子（vm.onTap）；仅当历史增长才触发 AI 应手（防重复触发）——防错 #1~#4 逐条保留。
- 各对战页信息区（回合/步数/用时/将军标记/走法记录开关）与操作按钮（新游戏确认框/悔棋/保存/分享）规格沿 Electron 版 §3.1~3.4。
- 残局工作室三 Tab、棋谱库/重放器、全局设置弹窗沿 §4~§6。

## 3.5 重复裁决交互（DR-006；useRepetitionJudge 移植规格）

- Hook 订阅 `moveHistory.length`，**仅增长时**调 `JudgeRepetition(fenHistory)`（回调经 ref 取最新值防重复触发）；
- VerdictPerpetualCheckWarning → 非阻塞 toast「红方/黑方连续将军重复，再次将判负」；
- VerdictPerpetualCheckLoss → `vm.resign(side)`（复用终局结算弹窗）；
- VerdictBothPerpetualCheckDraw / VerdictRepetitionDraw（对手非玩家）→ `vm.agreeDraw()`；
- VerdictRepetitionDraw（对手是玩家）→ ConfirmDialog「三次重复局面…接受和棋 / 变着继续」；拒绝 → declined 标志，k≥4 → 强制 agreeDraw；
- 历史缩短（悔棋）→ 重置 declined 与未决确认框；新局同理。

## 4. 识图人工校正流（沿 Electron 版 §4）

识图结果网格 → 棋盘上点击纠错 → 重新提交/直接采用；演示播放器（步进/自动/回退）规格不变。

**研究助手配置来源（Go 版扩展，DR-009）**：识图与求解辅助读助手槽，全空时运行时借用对战配置（黑→红，authSlot 随来源槽、不写入助手槽）；识图借用时消息区注记来源与"可能不支持识图"风险，求解辅助借用时 toast 提示。配置弹窗 UI 不变（动作时借用，不进配置界面）。

## 5. 防错清单（迁移验收逐项勾选，编号沿 Electron 版 §7）

#1 动画窗口忽略输入；#2 动画结束才落子；#3 历史增长才触发 AI；#4 悔棋/新局/离页 cancel 且丢弃迟到；#5 输入锁失败/取消/dispose 解锁；#6 终局后禁手；#7 存档恢复跳脏记录；#8 掩码 Key 不回写覆盖；#9 配置越界 clamp；#10 下载进度可取消且半成品保留；#11 k=2 长将警告不阻塞；#12 k=3 判负复用终局收尾（弹窗/PGN/DB 文案含判负方）。
