## 7. L3 重复局面裁决（DR-006 前置；electron-DR-018 final §5 的 Go 版规格）

**包**：`internal/rules/repetitionjudge.go`（纯函数，无状态，无 Zobrist 依赖——用 FEN 字符串比较，n≤数百微秒级）。

### 7.1 裁决 API

```go
type VerdictKind int
const (
    VerdictNone VerdictKind = iota
    VerdictPerpetualCheckWarning          // k=2 单方全程将军 → 警告
    VerdictPerpetualCheckLoss             // k=3 单方 → 判负
    VerdictBothPerpetualCheckDraw         // k=3 双方全程将军 → 不变作和
    VerdictRepetitionDraw                 // k=3 无人全程将军 → 判和（可拒绝一次）
    VerdictForcedRepetitionDraw           // k≥4 → 强制判和（不可拒绝）
)
type Verdict struct {
    Kind VerdictKind
    Side Side // 警告/判负的归责方
}
// fenHistory：完整局面 FEN 序列（长度 = 手数 + 1，含轮走方）
func JudgeRepetition(fenHistory []string) *Verdict
```

### 7.2 算法（逐条翻译 Electron 版 repetitionJudge.ts）

1. **重复识别**：统计 `fenHistory[len-1]`（最后局面）在历史中的出现次数 k 与各次出现索引（完整 FEN 相等比较，含轮走方）。
2. **环与归责**：`classifyCycle(fenHistory, prevIdx)`——环 = 最近两次重现之间的着法序列；第 i 手走子方 = `fenHistory[i]` 的轮走方（FEN 第 6 字段解析）；该手"将军" ⇔ `fenHistory[i+1]` 局面下其对手 `IsCheck`（含将帅照面）；结果缓存避免重算。归责 ∈ red/black/both/none（该方有手且**每手均将军**才算单方长将）。
3. **裁决状态机**：

| k | 环归责 | 裁决 | UI 动作（08 §3） |
|---|---|---|---|
| <2 | — | nil | 正常继续 |
| 2 | 单方全程将军 | PerpetualCheckWarning | 非阻塞 toast「X方连续将军重复，再次将判负」；闲着环/照面互将环**不警告** |
| 3 | 单方 | PerpetualCheckLoss | `vm.Resign(违规方)` 复用终局收尾 |
| 3 | both | BothPerpetualCheckDraw | `vm.AgreeDraw()`（不变作和） |
| 3 | none | RepetitionDraw | 对手是 AI/LLM → 自动 AgreeDraw；是玩家 → ConfirmDialog「接受和棋/变着继续」 |
| ≥4 | （玩家 k=3 拒绝过） | ForcedRepetitionDraw | 强制 AgreeDraw，不再询问 |

4. **无状态性**：悔棋=截断 fenHistory 后重算立即回到对应裁决；拒绝标志（declined）由 UI hook 持有（08 §3.5），历史缩短即重置——纯函数设计使回滚零成本。
5. **范围裁决（v1，与 Electron 版一致）**：不做长捉；不支持双打对单打复合长将情形（以"重现计数+环内将军归责"近似连续长将追踪）。

### 7.3 测试口径（09 §2.1）

- 手构三类金标准环 FEN（SWING 长将环 / QUIET 闲着环 / FACING 照面互将环）：k<2 nil、k=2 单方警告且照面环不警告、k=3 判负/不变作和/判和、k=4 强制和、截断后重算回到 k=2 警告。
- 与 Electron 版 `test/rules/repetitionJudge.spec.ts` 期望逐条一致（跨语言同 FEN 输入同裁决）。
