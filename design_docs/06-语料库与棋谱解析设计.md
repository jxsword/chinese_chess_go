# 06 语料库与棋谱解析设计（Go 版）

> 继承：`/home/ssy/proj/chinese_chess_electron/design_docs/06-语料库与棋谱解析设计.md`（§2 ICCS、§3 XQF 结构与解密、§4 PGN、§7 演示播放器为领域算法，Go 版逐行翻译其 TS 实现 `src/packages/parsers`）。
> 本文记录 Go 版差异：进程分工改单进程 goroutine（electron-DR-016 的替代）、IO 边界 Go 化。

## 1. 语料目录约定与扫描

沿 Electron 版 §1：语料根目录（Documents 下）、`corpus_manifest`（索引清单）、扫描去重；Go 版扫描在存储包（`internal/storage/corpus.go`），UI 经绑定方法调用。

## 2. ICCS 坐标格式（不变）

`b2-e2`（列 a-i + 行 0-9）——PGN/棋谱存储/LLM 清单共用；`internal/parsers/iccs.go` 的编解码与 Electron 版 moveCodes/parse 一致。

## 3. XQF 解析器（逐行翻译）

- 文件结构（棋谱头/棋盘/备注段）与 **Dong Shiwei 种子解密算法**（版本≥12 的置换与 keyRmkSize 处理）逐条沿 Electron 版 §3 与 `xqfParser.ts`；
- **验证策略（electron-DR-015 沿用）**：真实样例锚点（样例文件从 Electron 版测试资产复制到 `internal/parsers/testdata/xqf/`）+ 测试侧往返构造器；
- 批量回归：2911 个真实 XQF 文件批量解析（Electron 版 R6 门）——Go 版同样以"解析失败率 ≤ Dart 版"为门（大文件资产放本机不入库，CI 跑抽样集）。

## 4. PGN 解析器（逐行翻译）

- 预处理（标签对/注释剔除）、双着法格式（ICCS + 中文记谱并存）、**中文记谱消解算法**（歧义：同列同种多子 → 前/后/数序消解）逐条沿 §4.1~4.3；
- **大文件流式按局索引**（§4.4，electron R5）：`ScanGameOffsets(source, maxGames)` 逐字节扫描（`[Event]` 头识别 + 偏移记录 + 超长行按 moves 行处理、pending 不无限累积——P2-5 语义保留）；`ReadGameAt(offset)` 按需读单局；分页切片 128 局/页；
- 41743/99813 局两份验收基准文件的索引/分页行为与 Electron 版一致（大文件放本机，CI 用小样例 + 行为单测）。

## 5. 语料下载器（Go 化，安全设计逐条保留）

`internal/storage/corpusDownloader.go`：
- 仅 HTTPS；拒绝环回/私网/保留段/mDNS/IPv4-mapped IPv6/整数 IP/八进制分段（SSRF 白名单逐条沿 Electron 版 06 §5 测试表）；
- 流式写盘（`os.File` + 续传 sidecar ETag，语义沿 corpusDownloader.ts：块间超时 30s、abort 保留半成品+sidecar、完成清 sidecar、临时文件原子 rename）；
- zip 解压（`archive/zip`）：**zip-slip 防护**（`..` 越界/绝对路径/盘符/UNC/反斜杠归一/嵌套 ../符号链接/Windows 保留名含扩展形式/尾随点空格 全拦截，逐条测试沿 Electron 版 corpusDownloader.spec）；
- 进度经 `corpus:progress` 事件推前端（00 §3.2）。

## 6. 批量解析与浏览交互

electron-DR-016 的"Worker 分批 128 + generation 防陈旧"映射为 **goroutine 分批 128 + generation 计数防陈旧**（新扫描请求使旧批次作废，迟到的旧结果丢弃）；分批进度经事件推送。

## 7. 演示播放器（puzzle_vm）

沿 Electron 版 §7：步进/自动播放/悔棋回退/终局态——前端 TS 移植，Go 侧仅提供解析产物。
